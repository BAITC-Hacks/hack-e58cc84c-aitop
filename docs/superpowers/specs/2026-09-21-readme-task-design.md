# Дизайн README с техническим заданием

## Цель

Заменить черновое описание в `README.md` на короткое и однозначное техническое
задание для участников учебной разработки FAQ-бота.

## Аудитория и формат

README предназначен для разработчиков, которым нужно понять задачу до начала
реализации. Документ пишется на русском языке и остаётся компактным: только
контекст, обязательные требования, пример ожидаемого поведения и критерии
готовности.

## Структура README

1. Название проекта и краткая цель.
2. Описание задачи: терминальный чат отвечает на пять заранее известных тем.
3. Функциональные требования к `faq.txt`, поиску ответа и неизвестным вопросам.
4. Обязательные темы: время, команда, трек, сдача и призы.
5. Короткий пример диалога с известным и неизвестным вопросами.
6. Технические ограничения: стек свободный, достаточно ключевых слов, RAG не
   требуется.
7. Состав сдачи и проверяемые критерии готовности.

## Границы изменений

Меняется только `README.md`. README не должен описывать ещё не реализованные
команды запуска или заявлять о готовых результатах. Детали командной разработки
из `docs/DEVELOPMENT_PLAN.md` и `CONTRIBUTING.md` не дублируются.

## Критерии качества документа

- Все требования исходного README сохранены.
- Требования можно проверить без неоднозначного толкования.
- Пример не навязывает конкретную реализацию или точные тексты ответов.
- Документ легко прочитать за несколько минут.
- В тексте нет незаполненных секций и обещаний о готовой реализации.
