# Совместная работа без конфликтов

## Один человек — одна область файлов

Распределение владельцев и порядок интеграции описаны в
`docs/DEVELOPMENT_PLAN.md`. Не редактируйте чужую область без короткого
согласования. Особенно не меняйте одновременно `README.md`, `faq.txt` и общие
интерфейсы.

Если общий файл всё же нужно изменить, создайте для этого отдельный PR и
дождитесь его слияния до продолжения зависимой работы.

## Ветки

Не коммитьте рабочие изменения напрямую в `main`. Для каждой небольшой задачи
создавайте отдельную ветку:

```powershell
git switch main
git pull --ff-only
git switch -c feature/<имя>-<задача>
```

Примеры: `feature/alex-cli`, `feature/dana-matcher`, `feature/sasha-tests`.

Перед открытием или обновлением PR синхронизируйте ветку:

```powershell
git fetch origin
git rebase origin/main
python -m unittest discover -s tests
git push --force-with-lease
```

`--force-with-lease` допустим только для своей feature-ветки. Для `main` force
push запрещён.

## Коммиты и pull request

- Один PR решает одну задачу и по возможности меняет файлы одного владельца.
- Делайте небольшие смысловые коммиты: `feat: add keyword matcher`,
  `test: cover unknown question`.
- Перед слиянием нужен хотя бы один просмотр другим участником.
- Не нажимайте merge при красных тестах или неразрешённых комментариях.
- Для короткой истории используйте Squash and merge.
- После слияния удаляйте feature-ветку.

## Автоматические проверки

Workflow `.github/workflows/ci-cd.yml` запускается при каждом push и для каждого
pull request. Он проверяет синтаксис Python и запускает тесты из `tests/`, когда
эта папка появится. При успешном push в `main` дополнительно создаётся
скачиваемый артефакт приложения на странице GitHub Actions.

PR можно сливать только после успешного завершения job `Check and test`.

## Если возник конфликт

1. Не выбирайте автоматически целиком `ours` или `theirs`.
2. Откройте оба варианта и сохраните смысл обеих правок.
3. Для чужого файла позовите его владельца на совместное разрешение.
4. Запустите тесты и проверьте конфликтовавший сценарий вручную.
5. Завершите rebase командой `git rebase --continue`.

Не добавляйте в репозиторий виртуальные окружения, кэш Python, настройки IDE и
секреты: они исключены через `.gitignore`.
